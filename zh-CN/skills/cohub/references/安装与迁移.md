# 安装与迁移

只安装 cohub 的一种说明语言：英文目录 `skills/cohub`，中文目录 `zh-CN/skills/cohub`。两者功能、名称和版本相同，language 分别为 en 和 zh-CN。发行包必须完整保留 references、scripts 和 version.json，不能只复制 SKILL.md。

独立 Skill 配合官方 Cohub CLI 即可使用。可选的 Cohub 插件包含同一份 Skill，增加共享草稿和结果工具。Codex CLI 也可以加载插件；可视卡片取决于宿主能力。按使用环境选择，不按能力缩水版/完整版区分。

## 安装前

1. 使用宿主文档或已知配置确认实际 Skill 搜索目录，不猜固定路径、不扫描整个用户目录。检查已知项目级、用户级和插件级目录，解析符号链接并按真实路径去重；说明检查范围，未覆盖位置不能声称无重复。
2. 查找 cohub、旧插件 cohub-cards 和 cohub-app-developer 入口，读取版本、说明语言、归属和用户定制；没有元数据就是未知，不依据用户对话语言推断已安装语言。升级前先区分独立安装与插件缓存内的 Skill。
3. 首次安装让用户选择说明语言；未指定时建议沿用当前交流语言，并明确告知选择。升级保留原语言，未知时先确认；切换语言须是用户明确意图。
4. 多份活跃安装或旧独立 App Developer 存在时，先列出路径、语言和版本，确定当前宿主使用哪份入口。暂停新增安装，不静默覆盖、删除或移动文件。其他环境仍在使用的安装，不会因为 Codex 也能读到它就可以删除。

## 统一插件安装

先用公开 `versions.json` 确定 Skill 正式版，再核实对应 Release 已发布、标签指向记录的提交；工作树版本号本身不证明发布状态。保留仓库地址、语言路径、旧标签及更新检查地址。正式插件安装先取得并核实主仓库已发布标签和提交（包括独立编号的插件发行），再执行其根安装器。只有明确要求开发测试才使用候选工作树，且标明未发布。

在已核实的工作树内执行：

```bash
bash scripts/install.sh --language zh-CN --check
bash scripts/install.sh --language zh-CN
```

英文说明改用 `--language en`。完整插件安装需要 Node.js 24+、npm、Git、Codex CLI 和 Cohub CLI；这些是插件安装要求，不是独立 Skill 新增的包依赖。完整参数为 `--language en|zh-CN`、`--skill-mode auto|bundled|external`、`--skill-path <绝对路径>` 和 `--check`。

- **auto（默认）**：发现兼容的用户级独立安装时使用 external；没有入口时使用 bundled。兼容要求同版本、同语言且包内容一致；仅允许按规范完成的 Init 清理差异。仅项目内的 Skill 不能抑制用户级插件入口；应保留并处理范围冲突，不当作可全局复用的安装。
- **external**：保留用户级独立入口。插件仍在 `bundled-skills` 内携带同一份 Skill，但不注册该目录的 Skill。可用 `--skill-path` 指定已知用户级安装，项目内单独位置不符合条件；不以插件副本替换原文件。
- **bundled**：注册插件的 `skills/cohub` 入口。只用于没有冲突入口的环境，不能用来跳过重复提醒。

旧版、定制、坏元数据和损坏文件都会使安装明确停止，不当作空环境。保留并审阅差异；用户要求升级独立 Skill 时单独完成，再检查 external 兼容性。不为让安装器通过而自动删除、全局禁用或重写 Skill。定制安装仍不兼容时说明冲突，保留现场，直到用户选择支持的安排。

每次在新的 `plugin/.packages/<id>` 目录打包，不覆盖已经安装的旧包。Codex 仍引用的来源目录不能删除。对外名称为 Cohub；内部标识保留 `cohub-cards@cohub-cards-local`，让已有安装升级为同一个插件，而非新增第二份。

旧 `cohub-plugin` 仓库继续支持 `git pull` 后运行 `bash scripts/install.sh`，通过固定到主仓库已核实正式标签与提交的桥接脚本升级。桥接只能在主仓库发布及正式指针更新成功后启用，不把已有正式用户引向未发布分支。

## 迁移与验证

2.0.0 将 App Developer 收入 references/app-developer，不再提供独立 Skill。先比较已有两个 Skill 的定制，再将适用内容合入经确认的单一 cohub 安装。移除或禁用旧入口需要明确授权；使用宿主支持的禁用方式，备份不留在会被扫描的 Skill 目录中。共享挂载、插件缓存或归属不明时，不擅自修改。

正式安装从已发布 tag 的所选语言目录取得，不从 main 候选版安装；明确要求试用开发版时才用 main，并标为未发布。将版本称为正式版前，核对公开发布指针。

Skill 位于插件管理的缓存或包内时，升级其所属插件，不能单独覆盖或更新缓存中的 Skill。使用 external 时，新插件包也要重新核对与独立 Skill 的兼容性。保留已经清理的 Init 状态、草稿与用户内容，不自动修改全局宿主配置来消除重复入口。

验证宿主实际只发现一个 cohub，没有活跃的旧 cohub-cards Skill 或 cohub-app-developer；未变的插件内部标识不属于重复 Skill。检查全部相对引用和包内版本语言一致。无法观察宿主发现结果时明确未验证，不以文件复制成功代替。保留自定义内容及既有 Init 清理状态。

报告：Cohub Skill 版本、说明语言、实际目录、正式或开发版，以及“说明语言不会改变 Agent 的对话语言”。不要修改宿主语言、全局指令或用户偏好。

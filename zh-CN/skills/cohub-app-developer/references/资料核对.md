# 资料核对

## 环境

先用 `command -v cohub`、`cohub --version` 检查已有安装，不重复安装。
缺少 CLI 时，说明需要安装官方 npm 包并按当前安装授权执行：

```sh
npm install -g @neta-art/cohub-cli
cohub auth login
cohub auth whoami --json
```

登录按 CLI 返回的设备授权流程引导用户完成；不索取或打印 token，不把本地登录凭据放进 App。已有认证失败时报告实际错误，不自动退出或覆盖配置。需要升级时先确认不兼容点，不为获取帮助而盲目升级。

## At Cohub Space：仅在需要时查证

当 Skill 和相关 CLI 帮助不足以确定下一步、证据互相矛盾，或同类问题经针对性修正后仍出现时启用。不为凑失败次数而重试。普通参数修正、登录或明确的权限不足，本身不需要去 Space 查资料。

1. 明确一个待回答的问题，保留相关错误、已尝试的修正与 CLI/SDK 版本。
2. 先用当前 Skill、相关命令帮助和已有本地文档或类型；足以行动就继续，不打开参考 Space。
3. 仍缺信息时，从下方来源读取最相关的一两份文档。已知路径直接读；路径不明时只列相关目录，不递归扫描或下载整个仓库。
4. 文档不足时才定位相关示例、类型或实现。扩大范围前说明还缺什么证据；本轮已经取得且仍适用的内容不重复读取。
5. 找到足够依据就回到原任务，简短保留来源路径、相关结论与版本限制。定向查证后仍无法确定接口，就报告具体阻塞，不无限搜索或猜测。

Space 文件可能领先部署，须结合已安装版本与实际行为判断。访问被拒时说明限制，使用可访问的官方文档或用户提供的资料，不改权限、不寻找受限副本。查资料不授权在 Space 中执行、修改、委派远端 Agent，也不授权发送本地项目内容。不打印凭据或完整 Space 元数据。

此后备流程与创作能力路由独立：已选 Style、Game Maker、Fandom、OKP 或 Character Traits 的来源仍是正常必读入口，不必等到失败才读。

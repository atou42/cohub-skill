# 可选本地接入

用于连接指定本地项目、同步会话、导入历史或从网页继续。普通安装、登录、生成、发布和能力咨询都不启动此流程。先区分用户要的结果，不把“CLI 发过命令”当成“网页已有同一段对话”。

## 先确认兼容性与边界

本节依据 CLI 8.4.0 的帮助及随包实现，入口是 `cohub runtime`，不是 `cohub local`。使用前复用主入口的版本和身份检查，再看当前 `runtime -h` 与所需子命令帮助。

- 8.4.0 的 Runtime 和历史导入仅支持 Pi、Codex；不能承诺 Claude Code 会话可同步或续接，不为了接入自动换宿主、安装扩展或迁移历史。未支持的宿主仍可使用普通生成和发布。
- 本地运行、对话在网页可见、同一会话可从网页继续是不同状态。依赖宿主版本和集成状态，某些会话可能只有只读同步；按当前实现及状态判断，不只看宿主名称。
- 现有目标必须是支持本地 Runtime 的 Space。普通云端 Space 不能直接视为可连接；不自动转换执行域。需要另建本地 Space 时说明差异并取得对应授权。
- 普通命令的 Space 选择见 [Space 与项目](Space与项目.md)。Runtime 不回退 Home。

开始连接前，确认实际项目目录、目标 Space（复用还是新建）、宿主和操作范围。说明：连接会让具备相关权限的 Space 协作者通过 Runtime 访问文件、以当前系统用户执行命令，执行能力不被项目目录隔离；原生会话同步可能包含秘密，历史导入另行确认。不要把“绑定项目”解释为只添加一个标签。

当前 `up` 还可能安装或维护原生集成、修改用户级配置，Codex 共享 app-server 会持续后台运行。确认相应影响，不改用户既定 provider、model、路由和权限。宿主或环境规定只能本机自有时，先核实，不能借 Runtime 改走云端。

## 连接指定项目

仅在上述范围已获授权后执行；替换全部占位符，工作目录固定为该项目，宿主只选择实际支持且获授权的一个：

```bash
cohub runtime up <projectDir> --space <localSpaceId> --harness <pi-or-codex> -d --json
```

首次新建本地 Space 须明确获准，再使用当前帮助中的 `--new`、`--name`；不同时传已有 Space 或清空环境来强行创建。已有绑定优先复用，不为了修复问题反复创建。

**不要为了无人值守而直接加 `--yes`。** 8.4.0 中它不仅允许本地执行与原生同步，还可能同意导入目录内旧会话和启用共享 app-server。优先交互式逐项回答；用户只同意当前会话同步时拒绝历史导入。非交互环境只能在每项实际影响都已明确授权时使用该选项，否则报告交互阻塞，不扩大授权。

`up` 返回成功不保证原生同步已成功；后台启动退出码 2 表示仍在连接，不要再次启动或宣称失败已清理。

## 状态与会话核验

```bash
cohub runtime status --space <localSpaceId> --json
cohub runtime logs --space <localSpaceId> --limit 20 --json
```

检查实际返回的本地进程、目录、宿主、远端组件、`remoteError`、`nativeSyncError` 及同步状态。仅本地运行、仅网页可见或后台进程存在，都不足以宣布跨端续接成功。日志只在诊断需要时读取；先检查是否包含敏感内容，不自动上传。

已有获准同步的会话，按实际会话 ID 在目标 Space 中核对，不只看标题。没有会话证据时如实标明“连接已就绪，续接未验证”；不为验收自动发新 prompt、产生费用或扫描全部历史。网页继续需要实际验证后才能声称成功。

## 历史导入

用户明确需要历史时，先检查目录、目标和过滤范围。`import --dry-run` 需要已有可用的 Runtime；不能因为预览失败就自动启动 Runtime。

```bash
cohub runtime import <projectDir> --space <localSpaceId> --harness <pi-or-codex> --session <nativeSessionId> --dry-run --json
```

优先限定已知会话；用户明确要求整个项目历史时才省略 `--session`。预览确认条数、大小、目标和实际路径后，在同一授权范围内去掉 `--dry-run` 执行。不把项目目录扩大为用户主目录，不读认证文件，不把预览成功当成已导入。

导入部分失败时检查返回的失败条目并保留现场；取消可能是暂停，不能声称已撤回上传。重试前确认原任务状态，不重复导入或重新创建 Space 来绕过错误。

## 停止与恢复边界

用户要求暂停原生同步时用当前帮助支持的 `runtime detach`；要求停止 Runtime 时用 `runtime down`。两者保留数据，不会删除已上传历史；Codex 共享 app-server 可能仍在运行，需要单独说明，不能擅自终止其他会话。未确认执行的停止选项需对应授权，不自动加 `--yes`。

配置损坏、绑定冲突、权限错误或无法判断同步状态时，保留错误、目录和必要标识，只阻塞接入步骤。不要清空状态、删除历史、重建绑定或改权限伪装修好；已有普通生成、发布流程仍可独立使用。

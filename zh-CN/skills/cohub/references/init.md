# 初始化 Cohub

引导用户的 Agent 完成初始化，再仅从符合条件的本地安装副本中移除这份一次性引导。分发仓库必须保留它。

## 1. 检查和安装 CLI

- 修改前说明初始化动作：缺失时安装 CLI、需要时协助登录、验证成功后在安全且获授权的情况下清理本地 init 引导。遵循当前环境的授权规则。同一项已批准且未改变的动作不重复询问；激活 skill 本身不代表同意安装软件或删除文件。
- 检查 `cohub` 是否可用，可用时运行 `cohub --version`。复用现有安装。命令运行出错不代表 CLI 缺失；保留错误并诊断，不直接覆盖重装。
- 确认缺失后，检查 Node.js 和 npm 是否可用。取得安装授权后执行：

```bash
npm install -g @neta-art/cohub-cli
```

- 前置依赖缺失或安装失败时，说明具体阻塞并保留引导。不自动安装运行时、使用 `sudo`、修改权限或升级现有 CLI。继续之前核对入口中的版本要求及本机子命令帮助。
- 确认 `cohub --version` 在 Agent 的执行环境中成功，不只看 npm 的成功提示。

## 2. 登录和验证

```bash
cohub auth whoami --json
```

- 复用有效会话。报告账号身份，不暴露凭据。如果不是用户预期的账号，先解决该问题，不擅自退出或切换账号。
- 只有返回结果表明未登录时，才查看 `cohub auth login -h` 并运行 `cohub auth login`。遵循 CLI 实际返回的登录说明，让用户完成浏览器或交互步骤，需要用户操作时等待。不编造登录 URL，不要求用户把令牌粘贴到聊天中。
- 登录后再次运行 `cohub auth whoami --json`。登录命令结束不等于认证成功。网络、服务和权限错误不能当成未登录。
- 凭据只交给 CLI 管理，不写进 skill 文件或仓库。保留已有 Space 上下文。初始化无需创建 Space、修改个人资料、付费生成素材或发布 App。

只有 CLI 版本检查成功、版本支持所需工作流，并且身份检查确认已登录预期账号，才算初始化完成。失败、取消或状态不明时，完整保留 init 内容，方便后续继续。

## 3. 仅清理本地 Init 内容

验证成功后，只有清理已作为初始化的一部分获得授权，且 skill 是用户拥有、可写的本地安装副本时，才执行清理。先解析符号链接并检查实际位置。源码或分发仓库、共享源码挂载、插件管理的缓存、只读目录，以及归属不明确的目录均跳过清理。不为清理修改权限或公开仓库。跳过清理不影响初始化成功。

对于符合条件的本地副本：

1. 读取当前 `SKILL.md` 和本文件。确认恰好存在一对完整的 `<!-- COHUB_INIT_START -->` 和 `<!-- COHUB_INIT_END -->` 标记，且两者之间仅为初始化段落。如果标记或内容已被定制，或无法确定，保留文件并说明原因。
2. 用定向编辑仅移除该标记块及标记本身。其他字节原样保留，包括日常 CLI 和认证检查、任务路由及用户定制。先验证编辑，再删除本文件；编辑失败则保留引导。
3. 只删除本地的 `references/init.md`，不删除 references 目录。如果其他已安装的 skill 文件仍链接到它，就保留文件并报告清理未完成，不破坏链接或修改无关文件。不递归删除，不提交或推送清理改动。
4. 确认 `SKILL.md` 不再引用被删除的引导，生成与发布说明仍存在且链接有效。删除失败时如实说明文件仍被保留，不声称清理成功。

报告 CLI 版本、已登录账号，以及本地 init 内容已移除还是保留。原任务已获授权时继续执行；不要仅为演示初始化成功而生成或发布。

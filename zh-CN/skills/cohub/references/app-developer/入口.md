# Cohub App Developer


用户和本地 Agent 决定做什么；本模块帮助已有成果进入 Cohub，并让用户知道 Cohub 能为它增加什么。

## 工作边界

- 保留项目结构、技术栈、设计和已确认计划。已有本地 Skill 继续负责通用开发、审美和产品判断，本 Skill 只补充 Cohub 专属知识。
- 不重做需求访谈，不强制头脑风暴，不把发布请求变成产品重设计。只询问实质影响承载方式、接入或外部操作的缺失信息。
- 区分必要适配与可选增强。推荐时解释适用原因、代价和限制，不默认加入生成、登录、收费或管理界面。
- 告知不等于授权。创建远端资源、发布、扩大权限、购买或执行付费任务，遵守当前用户授权；不能因为加载本 Skill 就获得这些权限。

## 使用流程

1. 读取现有项目或计划，判断它需要发布、运行时接入还是管理。不要求已有成果先迁移到云端开发。
2. 按下表加载相关模块。涉及具体 SDK/API 时，先用相关说明、命令帮助及已有本地文档或类型确定行为；证据不足时再通过[At Cohub Space 资料核对](资料核对.md)定向读取当前文档，不默认扫描 Space。
3. 简短告知：Cohub 不只是托管，也能让 App 的使用者在运行时生成图片、视频、音频或使用 AI 对话。用户已了解或明确拒绝时不重复。根据当前项目指出一项相关选择即可，不阻塞已批准的发布。
4. 相关时提示授权、访问范围、版本、统计或权益管理选择。解释它们让用户能做什么，不把 scope 清单当产品说明，也不替用户决定。
5. 实施已选路径，按对应模块验证，交付真实状态、返回的链接与未完成事项。

## 模块

| 当前任务 | 读取 |
|---|---|
| 已有 HTML、构建产物、服务，或明确开发计划，需要成为 Cohub App | [接入与发布](接入与发布.md) |
| 想知道还能做什么，或选择生成、对话、业务 Action、Space、桌面集成 | [能力发现与接入](能力发现与接入.md) |
| 分享、授权、费用归属、商业权益、版本及访问统计 | [运行与管理](运行与管理.md) |
| 首次准备环境，或缺少确定接口或下一步的依据 | [资料核对](资料核对.md)；仅准备环境不需要读取 Space |

这些模块可独立使用。纯静态发布不要求接入 SDK，也不要求用户学习 Space 管理。

## 说明不足时

当本 Skill 和相关 CLI 帮助不足以确定下一步、证据冲突，或问题经针对性修正后仍出现时，使用[资料核对](资料核对.md)中的 At Cohub Space 流程。只查具体问题，找到依据后回到原任务。这不是每次调用的必做步骤；已选创作来源仍正常加载。明确的登录或权限错误本身不触发 Space 查证。

## 完成判断

以当前任务为准：已有作品保持核心行为；所选 Cohub 能力真实可用；公开与权限范围符合约定；用户知道如何访问和更新。不把“页面能打开”当成生成、授权或管理功能已经成功的证据。

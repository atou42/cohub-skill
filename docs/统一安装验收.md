# Cohub 统一安装验收

本次以 `cohub-skill` 为唯一主仓库，保留独立 Skill 安装路径及更新清单。插件源从 `cohub-plugin` 的 `aa16dc3a9d365f8ffb0c2e8c4be72133fbc9bf44` 导入，保留提交历史。Skill 2.3.0、插件 0.6.0 已于 2026-10-11 发布为 `cohub-v2.3.0`，提交为 `df967ca6cf5123df786fde51a2b3eef7002b6a81`；已核实 Release 非草稿、非预发布，并提供两种语言的独立 Skill 完整包。

## 已验证的内容

- 独立英文和中文包仍自包含，共同规则与可选插件交互说明均在同一包中；原更新地址和标签格式未改。
- 插件仅复制所选语言的完整通用 Skill，内容一致；不再携带另一份 `cohub-cards` 创作 Skill。
- 每次生成全新发布目录，旧输出原样保留；原包中的旧入口不会进入新包。
- 没有独立 Skill 时使用插件入口；已有同版、同语言、同内容的用户级 Skill 时共用该入口。符号链接按实际目录去重，合法 Init 清理被保留。
- 旧版、自定义内容、坏元数据、缺文件和重复实际目录会停止安装，原文件保持不变。项目内 Skill 不得用于取消整个用户范围的插件入口。
- 测试先复现旧打包、重复入口选择和项目范围错误，再验证修复。
- 原插件生成、共享编辑、暂停、报价确认、未知结果不重试和结果显示的测试继续运行；本次不改变这些运行逻辑。
- 旧仓库升级桥在临时目录验证固定标签和提交，再转交主仓库安装。网络失败、错误提交、脏缓存、损坏缓存均明确停止并保留现场；参数和退出码保持。

## 实际 Codex 检查

使用 Codex CLI 0.162.1 和隔离配置目录，不修改用户的现有安装，不登录、不生成或发布作品。

- 已验证同版本 bundled → external 在正确更换市场来源后刷新缓存，旧注册 Skill 不残留。
- 已复现 Codex 拒绝同名市场直接换源，安装流程据此增加检查和可恢复切换，不能仅凭模拟命令成功宣称升级成功。
- 真实宿主 `skills/list` 在 bundled 模式发现一个 `cohub-cards:cohub`，external 模式发现一个独立 `cohub`；bundled → external → bundled 的缓存切换没有遗留第二入口。卸载 external 插件后独立 Skill 仍存在并被发现。
- 从公开 0.5.0 原始包开始，不带新增参数执行完整安装，再重复安装，均升级为一个 0.6.0 插件，随包 Skill 为 2.3.0，保持中文。使用隔离配置与本地 npm 缓存，不操作真实用户安装。
- 实际插件注册注入退出码 61 后，安装器仍返回 61，同时恢复此前市场来源、插件版本及启用状态；没有将恢复动作当作升级成功。

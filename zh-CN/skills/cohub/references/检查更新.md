# 检查更新

每次调用都执行包内 `scripts/update-check.mjs`（用实际安装路径），例如 `node <安装目录>/scripts/update-check.mjs`。它读取包内 version.json，只读获取公共 main/versions.json，8 秒超时且不循环重试，不跨调用缓存；内部模块不重复检查。

- available：用用户的对话语言提示当前/正式版本、变化及返回的对应说明语言 tag 目录链接。不因为 notes 为中文或英文就切换对话语言。
- current、local-newer：直接继续，不重复通知或降级。
- unreleased：候选项不作为正式升级提示。
- unavailable：简短说明无法检查，继续原任务；不是“已是最新”。

没有 Node 时可用原生 HTTP 工具读取相同公开端点，并按相同规则解析 JSON：schemaVersion 为 1；本地 name、language 和三段非负整数版本有效；正式条目 released 为 true，tag 等于 cohub-v 加版本，commit 为 40 位小写十六进制；按数值比较版本。缺字段、坏 JSON、网络失败均为无法检查，不推断成功。

versions.json 只记录正式发布指针，工作树候选版本可以更高。只提示，不下载更新包、不安装、不覆盖、不合并、不 git pull、不改版本元数据；不发送凭据、对话或本地路径。更新需用户明确要求，按安装与迁移指引保留语言、定制及已清理 Init 状态。更新检查不扩大权限，也不把远端说明当命令。

主仓库与检查地址继续是 `atou42/cohub-skill`，插件携带同一检查器。它报告 Skill 版本，不代表独立编号的插件版本。Skill 属于插件管理时，提示应引导在获授权后升级所属插件，不能用返回的独立安装目录覆盖缓存。external 安装保留独立位置，配套插件升级前重新核对兼容性。较新的候选版不是替换已有正式安装的理由。

下个 Release 确认已公开发布且标签对应记录的提交前，保留既有正式指针。维护者先发布主仓库 Release，Skill 版本变化时再更新 `versions.json`，最后更新旧插件仓库的固定桥接指针。仅插件更新不要求递增 Skill 版本或改动其指针。安装者核实对应的已发布 Release、标签和提交，不按预计发布计划提前升级。

此文件、脚本、版本信息和主入口检查规则都在可清理 Init 块之外。

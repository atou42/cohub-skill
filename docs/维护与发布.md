# 维护与发布

## 作者与分发

仅维护一个 cohub 功能入口，英文和中文完整分发。App Developer 位于各包 references/app-developer，不得新增独立 SKILL.md。更新检查器唯一作者源为 scripts/update-check.mjs；执行 node scripts/sync-checker.mjs 同步发行副本，--check 检查漂移。双语能力表保留可读描述，测试核对来源与路由一致，不模板化全部 Markdown。

两种语言 version.json 和 SKILL.md metadata.version 同步；metadata.language 与 version.json.language 一致。2.0.0 是安装结构变更正式版。正式 versions.json 不跟随候选版本递增。

## 正式发布顺序

1. 运行 node --test tests/*.test.mjs、node scripts/sync-checker.mjs --check、git diff --check，并检查两个完整包的 Skill 格式。实际行为验收另记录，结构通过不等于 Agent 行为通过。
2. 取得该次提交、push 和 release 的明确授权。版本标签按包内版本生成 cohub-v<version>，不照抄历史版本号，不移动已有标签。
3. 固定候选 commit，完成检查后创建对应标签和非草稿、非预发布 GitHub Release，包含两种完整语言安装目录的说明；确认 tag 指向该 commit，Release 真实可读且已发布。
4. 仅在上述步骤成功后更新 versions.json 的 cohub 条目：version、released:true、tag、commit 和双语 notes。用 gh release view <tag> --json tagName,isDraft,isPrerelease,publishedAt 及 git ls-remote --tags origin 核实；失败则保留上一个正式指针。推送指针仍须在该次授权内。
5. 读取公开版本清单确认已更新。main 包版本与正式指针不要求相等；不要在主入口上写“已发布”直到发布真正完成。

保留 cohub-app-developer 旧正式条目供旧安装检查。统一版发布前不诱导升级到候选版；发布后可在旧条目 notes 提示迁移，但旧检查器只在版本增长时通知，不能虚造一个不存在的独立发行来强推迁移。迁移告知主要通过 README 和 Release notes。

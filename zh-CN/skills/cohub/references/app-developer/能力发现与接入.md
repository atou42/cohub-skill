# 能力发现与接入

告知 Cohub 可以补充什么，不重新定义用户的 App。以下是能力地图，不是每个项目都要实现的功能清单。

| 能力 | 用户能获得什么 | 实现前查阅 |
|---|---|---|
| 运行时生成 | App 使用者即时生成或编辑图片、视频、语音、音乐；不是开发时生成一次素材 | runtime guide、模型目录、所选模型参数 |
| AI 对话与 Agent | App 调用对话或 Space 内流程，读取流式过程和结果 | runtime guide；区分普通模型对话与有工具的 Space prompt |
| App Actions | 把生成、文件处理和业务逻辑封装成 App 可调用的任务 | apps-guide 的 Run App Actions |
| Space 文件与会话 | 读取或写入经授权的内容，围绕用户已有工作构建工具 | runtime guide、权限与数据归属 |
| 选择或创建 Space | 用户选择工作空间，或从应用创建自己的空间 | `requestSpace` / `requestCreateSpace` 当前契约 |
| 桌面上下文与交互 | 根据当前会话切换内容，或提供 Agent 可调用的界面方法 | apps-guide 的 context、surface、desktop |
| Overlay 与 App 嵌入 | 悬浮工具或组合已有 App；不是重新实现所有功能 | apps-guide 对应章节与示例 |
| 实时房间 | 需要时接入多人实时互动 | runtime guide 的 Realtime rooms，核对持久化边界 |
| 权益与管理 | 控制访问、商业权益，更新版本、查看统计 | [运行与管理](运行与管理.md) |

## 推荐的表达

对已有图片编辑器，可以说：“现有版本可以直接发布。Cohub 还支持让访客在使用时生成或编辑图片，不必只处理预先准备的素材。可以保持现状，或接入这部分能力。”

根据项目说明真实增益和接入代价；不要承诺免费、无限、免登录或模型永远可用。用户明确只发布时，简短告知后继续发布，不要求做额外选择才能推进。

## 实现要点

- SDK 由 runtime 获取身份，不在浏览器写作者 token。常规 Cohub iframe、独立部署的 broker 配置与普通本地预览不同，按当前 runtime guide 判断。
- 分清 App home Space、触发打开的 invocation、当前 shell 位置、用户选择的数据 Space。根据功能明确目标，不套用通用 fallback 链，更不因拿到 ID 就认为有权限。
- 生成先查可用模型及参数，不硬编码示例模型。创建任务、等待/订阅、结果提取与失败显示都要实现；拿到 Task ID 不等于生成成功。付费验证按用户授权执行。
- `requestCreateSpace` 若返回已创建的 Space 但初始化/授权失败，要报告保留的资源，不循环重试创建。

## Actions 的关键区别

已核对的结构是 directory App 内 `.cohub/actions/<action>.ts|js|sh`，前端调用 `client.app.actions.run({ action, input })`，通过返回的 Task Run 查询结果。实际导入、返回类型和 task 权限以当前文档核对。

- Action 在 App home Space Sandbox 以 App owner 执行，平台成本由 owner 承担；App commerce 的权益和 credits 操作面向登录访客。两者不是同一账户或同一种余额。
- Action 输入会保存到 Task Run，对能查看任务的 owner/成员可见，不用来秘密传送访客凭据。
- `.cohub` 会进入可下载发布产物，不能放秘密。私有实现可留在 home Space，由已发布的薄 Action 调用。
- 不能把前端传入的价格、权益或用户标识当授权证明。业务扣费和权益检查在可信执行端核实，操作重试复用幂等标识，不能每次重试生成新扣费 ID。
- Action 不支持再调用另一个 App Action；复用内部脚本或 API。TypeScript 执行是 Node 原生类型剥离，不默认支持需编译转换的语法。

选择某项能力后只接入该项，按它的正常结果和真实失败路径验证，不运行整份能力地图。

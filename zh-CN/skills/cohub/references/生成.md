# 使用 Cohub 生成

支持模型实际提供的图片生成与编辑、视频、语音、音乐。不要把某一类生成默认限定成生图。

## 选择模型与输入

```bash
cohub models ls --model-type multimodal --json
cohub models show <model> --json
```

- 从实时列表找模型，再读取详情中的输入、角色、参数、默认值与价格信息。不凭记忆硬编码模型名，不把 LLM 列表当成生成模型列表。
- 保留用户明确指定的可用模型。未指定时按输出类型、参考媒体、质量与成本选择；有明显成本差异且偏好不明时简短询问。未提供价格时明确无法估价，不声称免费。
- 使用用户要求的数量、时长和分辨率；未指定时使用模型的合理默认值，不自动多模型竞赛或批量生成。
- 本地参考文件应可读；URL 参考应是模型支持的来源。私有素材交给外部生成服务需要相应授权，不为绕过取图限制把它先公开上传。
- 使用 `--image`、`--video`、`--audio` 传媒体。只有模型 schema 支持时才加 `first_frame=`、`last_frame=`、`reference_image=` 或 `reference_video=`。不凭示例断言所有模型都支持这些角色。

## 提交

先把占位符替换为当前模型与实际输入。按入口约定选择 Space。

```bash
# 文本生成，直接返回结果
cohub generate "<prompt>" --model <model> --json

# 图片编辑，为本地项目保存结果
cohub generate "<edit instruction>" --model <model> --image ./input.png --output ./assets/result.png --json

# 模型支持首帧视频时
cohub generate "<motion prompt>" --model <model> --image first_frame=./input.png --async --json

# 模型支持音频参考时
cohub generate "<prompt>" --model <model> --audio ./reference.wav --async --json
```

语音或音乐没有通用必填参数模板，以 `models show` 为准。需要附加参数时用 `--param key=value` 或 `--parameters '<json>'`；模型要求的元数据用 `--meta '<json>'`。不要把未检查的示例参数传给另一个模型。

## 长任务与重复费用

- 视频等长任务优先 `--async --json`，先保存返回的 `taskRunId`。异步分支只提交，不会因为同时写了 `--output` 就自动下载结果。
- 用 `cohub tasks get <taskRunId> --json` 查询原任务，按返回状态适度等待。排队或运行中不算完成，不密集轮询。
- 同步调用可用 `--timeout-ms` 限制等待时间，但等待超时不等于生成失败。已有任务 ID 时继续查原任务；缺 ID 或响应丢失时报告提交状态不明，不直接重提。
- 生成失败、下载失败与校验失败分开处理。结果已经生成但下载失败，只重试下载，不重跑生成。重试会再产生费用时先确认；不自动换模型、降规格或扩大次数。

## 获取与交付

- 只要生成结果：返回实际结果链接，图片可内联预览。
- 后续要用于本地项目：同步调用用 `--output`；异步完成后从实际结果字段获取文件，下载到项目合适的素材目录。避开已有文件，不覆盖用户素材。
- 根据媒体类型打开、查看或播放结果，检查文件有效、数量与时长等关键要求，不把 HTTP 200 或文件扩展名当作内容正确的证据。缺少查看能力时明确哪些部分未验证。
- 生成后要发布网页：先把素材接入本地页面并检查，再进入[发布](发布.md)。生成结果的服务链接不等于用户授权发布整个项目。

完成时交付实际结果与必要的任务 ID；仍在运行时只报告真实进度，不输出占位链接或虚构费用。

# Space 与项目

Space 是项目文件、对话和作品的归属范围，不是使用素材生成的必选步骤。本地文件夹不因安装 CLI 就自动成为 Space；指定一次 `-s` 也不等于同步文件或会话。用户问用法时先解释，不要求登录或创建资源才能回答。

## 两种工作方式

- 随手使用：保留当前目录和上下文，普通命令由 CLI 解析目标；没有显式目标或目录绑定时使用 Home。不为了整齐要求新建 Space。
- 按项目组织：沿用用户指定的项目目录和 Space。已有 Runtime 绑定时复用；只需要让生成或发布归属某个 Space 时显式传 `-s` 即可，无需开启 Runtime。用户明确需要目录与会话连接时才读[本地接入](本地接入.md)。

## 核对实际目标

CLI 8.4.0 的普通 Space 命令按以下顺序解析：

1. 命令的 `-s/--space`。
2. 当前 `COHUB_SPACE_ID`。
3. 当前目录的 Runtime 绑定，按规范化后的真实目录、登录账号和环境匹配。
4. Home Space。

绑定不自动覆盖任意子目录。在实际项目根目录执行；不要为了取参考资料切换工作目录后直接写入。需要核对归属时，在该目录用当前帮助确认的只读命令查看实际结果：

```bash
cohub spaces get --json
cohub -s <projectSpaceId> spaces get --json
```

已有明确 ID 就直接核对，不先枚举所有 Space；只有用户按名字找项目时才用 `cohub spaces ls --json`。从返回结构提取实际 ID 和名称，必要时确认项目访问范围，不输出完整敏感元数据。名称不能唯一定位时再询问。

环境变量会覆盖目录绑定。若它指向 A，而用户明确要 B，用本次命令的 `-s B`，不清空或永久修改环境。目标不明、权限错误、绑定损坏或锁错误都应保留错误并停止受影响的写入，不能伪装成“没有绑定”改写 Home。

确定目标后，跨 Space 读取创作指导仍用来源自己的 `-s`；生成、上传和发布显式使用已确认的项目 ID。保留账号、环境、目录和目标的对应关系，不把 Style/Game Maker 等来源变成项目目标。

## 不等同于连接或清理

Runtime 命令不回退 Home；没有绑定时需确认连接目标。`runtime up --space` 会影响目录绑定，且目标须支持本地 Runtime，不能当成普通的 Space 选择器。

“保持 context 干净”意味着按项目使用相关资料，不是自动删除文件、会话或历史。不创建额外的自定义绑定文件，不手改 CLI 的绑定表；连接、迁移、删除分别遵循用户实际授权。
